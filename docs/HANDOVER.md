## 1. アプリのコンセプト

### 目的
日本基準（J-GAAP）で決算をしている子会社の財務数値から、IFRS へ組み替えるための **調整仕訳（AJE）** を起票するWebアプリのプロトタイプです。親会社がIFRSで連結決算をする企業グループを想定しています。

### 使う人
- **子会社の経理担当者**：資料を提出し、収集パッケージ（様式）に入力する。
- **親会社の連結決算担当者**：資料を確認し、計算・確定して、連結精算表で集計する。

### 考え方
- **ブラックボックスにしない**：仕訳の1行 → 計算シートの行 → 明細 → 元資料（原本とハッシュ値）までたどれる。計算を再現して検証できる。
- **会社×期×論点で管理する**：進み具合は「未着手 → 取込済 → チェック済 → 計算済 → 確定」。確定すると DB 側でロックされる。
- **方式（仕訳区分）**：BTrex（連結会計システム）の開始仕訳の方式に合わせる。
  - 累積：当期の変動分を出力する。
  - 洗替：期末の全額を出力する。
  - 組換：当期の全額を出力し、翌期に引き継がない。
- **四半期に対応**：四半期は期首からの累計で計算する。前期は前年度の期末で、前年度末の確定した残高から計算する。
- **プロトタイプの前提**：ダミーデータで、ログインはない。URLを知っていれば誰でも読み書きできる（実データは入れない）。

画面の上部で「前期／当期 × 1Q・2Q・3Q・期末」を切り替えます（選んだ時点はブラウザに保存）。

### 作業画面
- **時点の帯**：四半期・期末を行き来できる。点の色はその論点の状況。
- **1. 取込**：明細の入れ方を3つから選ぶ。
  - ファイル取込：会計ソフトの出力をそのまま取り込む。列名が違っても、見出しの行と列の候補を自動で選ぶ。選んだ対応は会社の列マッピングとして保存できる。
  - 1件ずつ入力：Excel から貼り付けもできる。
  - 合計で入力：精度を保つまとめ方を案内する。有給休暇は区分ごと・残日数で加重平均した日額給与、減価償却は資産の種類×取得年月。
  - 手入力も CSV にして元資料として保存し、ハッシュ値で確かめられる。
- **2. 明細チェック**
- **3. 計算シート**：計算の検証（再計算して保存結果と比べる）、前提値のスナップショット、橋渡しの図。前の計算があるときは、再計算する前に科目ごとの上書き前後・差額を確認する画面が出る。
- **4. 仕訳・確定**：根拠をたどる（仕訳 → 計算シート → 明細 → 元資料のハッシュ値）、CSV 出力、確定と確定の解除。
- **計算を実装していない論点**：収集パッケージから作った仕訳の確認・確定と、様式へのリンクだけを出す。

### 収集パッケージ
- 様式の定義は `src/lib/materials.ts` にある。入力例・見る場所・用語の説明つき。
- 前期の値を並べる。残高（BS）は前年度末、期間の金額（PL）は前年同期、どちらも直前四半期。30%以上変わった項目は理由の入力を求める。
- 自動保存、全角数字や「△」の読み替え、整合チェックがある。
- 提出 → 親会社の確認済／差し戻し。入力者名は必須で、ブラウザに覚える。
- 上部のバーに、入力者・下書き保存・提出・次の様式へ・確認済にする・差し戻すをまとめている。
- **仕訳のプレビュー**（`src/lib/preview.ts`）：金額を押すと、参照している入力欄を色で強調する。
- **Excel**：ダウンロード（入力欄以外は保護、選択肢は入力規則）と取り込み。取り込むのは変わった様式だけで、下書きとして入る。

### 連結精算表（`src/lib/consolidation.ts`）
- **当期仕訳**：選んだ時点の各社の計算の仕訳。下書きを除くこともできる。
- **開始仕訳**：前年度までの**確定した**計算から作る。
  - 累積：前年度までの累計。
  - 洗替：前年度末の全額。
  - 損益は利益剰余金に、OCI はその他の資本の構成要素に置き換える。組換は引き継がない。
- **開始実現仕訳**：洗替の論点で、前年度末の全額を期首に戻し入れる。
- **精算表**：
  - 関係する科目だけを、資産・負債・純資産・損益・OCI の順に並べる。
  - 列の切り口は「仕訳の種類」「論点別」「会社別」。借方そのまま、貸方は△。
  - 金額の大きさを色の濃さで示し、貸借の検証（0）と当期利益・包括利益への影響の行を付ける。
  - セルを押すと内訳（会社×論点×仕訳区分）が出る。Excel・CSV で出力できる。
- **グラフ**：純資産への影響の橋渡し、論点別・会社別の当期利益への影響。
- **上書き前後**：「集計する」でいまの金額を記録する（`consolidation_snapshots`）。チェックを入れると、各セルに前の金額と差額が出る。
- **注意の表示**：当期の計算がない会社×論点、明細を入れ替えて再計算を待っている会社×論点。
- **決算日が違う会社**：12月決算の S10 は、3か月前までの期を使う。

### テストデータ（マスタ →「テストデータ」タブ、`src/lib/testData.ts`）
- **入れる**：全17論点 × 全社 × 6時点（前期の1Q〜期末、当期の1Q・2Q）。約75秒。前のテストデータだけを入れ替え、画面で入力したものは残す。
  - 収集パッケージ（全様式、当期2Qは提出済・入力中・差し戻しも）と、試算表の提出。
  - 有給休暇・減価償却：アプリの取込・計算・確定の処理そのもので作る。S01 は手で試すため空ける。
  - ほかの論点：収集パッケージから簡易計算し、計算・仕訳・確定として保存する（当期2Qの一部は下書き）。
  - 方針の上書き：のれん（S02・S05・S08）、株式報酬（S03・S09）、償却原価（S04・S06・S10）を「適用」にする。
  - 連結精算表の集計（当期2Q）のあと、S03 の有給休暇を訂正する（上書き前後を見せるため）。
- **全て消す**：テストデータだけを消す。「画面で入力したものも消す」にチェックを入れると、マスタ以外を全て消す。方針の上書きは元に戻す。
- **コマンドで入れる**：`npx vitest run --config scripts/vitest.seed.config.ts`
- **件数の確認**：DB 関数 `test_data_counts()` で、テストデータ／画面で入力したものの件数を1回で数える。

## 4. 論点（17）

一覧は `docs/issues_list.md`、解説の本文は `src/lib/help.ts` にあります。

| No. | コード | 論点 | 計算 | 方式 |
|---|---|---|---|---|
| 1 | PAID_LEAVE | 有給休暇引当金 | 計算まで実装（`src/calc/paidLeave.ts`） | 洗替 |
| 2 | LEVY | 賦課金（固定資産税・均等割） | 簡易計算 | 洗替（均等割は組換） |
| 3 | DEPRECIATION | 減価償却（経済的耐用年数） | 計算まで実装（`src/calc/depreciation.ts`） | 累積 |
| 4 | RETIREMENT_1 | 退職給付①（即時認識・純利息） | 簡易計算 | 累積 |
| 5 | RETIREMENT_2 | 退職給付②（割引率・期間帰属） | 簡易計算 | 累積 |
| 6 | EQUITY_INSTRUMENT | 金融商品（株式） | 簡易計算 | 累積 |
| 7 | GOODWILL | のれんの非償却 | 簡易計算 | 累積 |
| 8 | COMPRESSION | 圧縮記帳の取消し | 簡易計算 | 累積 |
| 9 | ARO | 資産除去債務の割引率 | 簡易計算 | 累積 |
| 10 | SHARE_BASED | 株式報酬費用 | 簡易計算 | 累積 |
| 11 | EIR | 償却原価（実効金利法） | 簡易計算（`src/lib/eir.ts` で実効金利を計算） | 累積 |
| 12 | DEVELOPMENT | 開発費・繰延資産 | 簡易計算 | 累積 |
| 13 | TAX_EFFECT | 税効果（回収可能性・税率差異） | 簡易計算 | 累積 |
| 14 | ECL | 金融資産の減損（予想信用損失） | 簡易計算 | 洗替 |
| 15 | IMPAIRMENT | 固定資産の減損 | 簡易計算 | 累積 |
| 16 | PROVISION | 引当金の取消し | 簡易計算 | 累積 |
| 17 | LT_BENEFITS | その他の長期従業員給付 | 簡易計算 | 累積 |

- 外した論点：リース（IFRS 16）と表示の組替え（依頼者の指示）。
- **簡易計算の要点**：
  - 期間の金額の論点（のれん償却・開発費・数理差異・株式報酬）は当期の累計。
  - 残高の論点（割引率・株式・圧縮・資産除去債務・償却原価・回収可能性・減損・引当金・長期給付）は前年度末からの増減。
  - 洗替は期末の全額。
  - 株式報酬と回収可能性は、テストデータ専用の計算（`testData.ts` の `customEntries`）。
- **償却原価**：元本は満期に一括返済、利息は毎月払い、月単位で計算する前提。金利が市場より低い契約は、市場金利で割り引いた額で当初計上する。返済条件の変更は対象外。
- **予想信用損失**：方針 `loss_rates`（延滞日数5区分）と `credit_impaired_rate` を使う。
- **論点を追加する手順**：
  1. マイグレーションで論点・仕訳区分・統一科目・方針を追加する。
  2. `materials.ts` に様式と資料を追加する。
  3. `preview.ts` に計算を追加する。
  4. `testData.ts` の `GEN` と `PACKAGE_ISSUES` に追加する。
  5. `help.ts` に解説を追加する。
  6. 試験（`preview.test.ts`）を追加する。

### 主なテーブル
- **マスタ**：`companies`、`periods`（Q1・Q2・Q3・FY。四半期の開始日は年度の開始日。`prior_period_id` は前年度の期末）、`issues`、`journal_categories`（`carry_method`）、`group_accounts`、`column_mappings`、`asset_class_rules`、`policies`（会社ごとの上書き ＞ グループ共通）
- **取込・計算**：`source_files`（`file_type` は excel・csv・pdf・manual）、`detail_items`、`calculation_runs`（draft・final・superseded。有効な計算は1つだけ）、`calculation_steps`、`item_balances`、`journal_entries`、`journal_lines`
- **管理**：`work_status`（`locked` で確定ロック）、`change_logs`（トリガーで自動記録。画面からは読み取りのみ）
- **収集・連結**：`package_entries`（会社×基準日×様式）、`consolidation_snapshots`
- **ビュー**：`v_policy_matrix`、`v_progress`、`v_impact_summary`、`v_unbalanced_entries`、`v_missing_carryforward`

### 大事な仕組み
- **確定ロック**：確定（`work_status.status = 'locked'`）の会社×期×論点は、明細・計算・仕訳の変更を DB が拒否する。消すときは、状況（`work_status`）を先に消してから、仕訳 → 計算 → 明細の順に消す。
- **再計算待ち**：明細を入れ替えても、確定前の計算は「再計算待ち」として残す（計算シートから明細への参照だけ外す）。再計算のときに上書き前後を比べるため。
- **`is_demo_seed`**：テストデータの目印。対象は `package_entries`・`source_files`・`detail_items`・`calculation_runs`・`work_status`・`consolidation_snapshots`・`policies`。

## 6. ソースの構成

```
src/
  App.tsx                 メニュー・ルーティング（画面は分割読み込みしない：分けると初回表示が約2割遅くなったため）
  index.css               全体のスタイル（配色テーマ、--viz-*・--cat-* の色）
  calc/                   有給休暇・減価償却の計算（画面から切り離した関数。試験あり）

  lib/
    supabase.ts           接続
    hooks.ts              useAsync（対象が変わったら前の結果を出さない）、時点（Slot）
    masters.ts            マスタの読み込み、periodFor（会社×時点の期）
    workflow.ts           取込・チェック・計算・確定（DB の読み書き）
    issues.ts             計算まで実装した論点の取込定義（列・手入力・合計入力）
    materials.ts          資料と収集パッケージの様式
    package.ts            収集パッケージの読み書き・入力チェック・提出状況
```

## 8. 注意点（これまでにつまずいたこと）

- **1000行の上限**：Supabase の API は1回に1000行までしか返さない。ビューや時点×論点の問い合わせは、時点の種類（`period_type`）や期で絞るか、分けて読む。四半期の追加時と論点17化の時に、この上限で表示が切れる不具合を出した。
- **変更履歴が増える**：テストデータの入れ直しのたびに変更履歴が増える（約8万件）。0013 の索引で検索は速い。
- **表示速度**：一覧画面は、マスタと他の問い合わせを同時に出す。マスタを読んでから問い合わせると遅くなる（実測で約0.4秒遅くなったことがある）。
- **Supabase MCP**：`apply_migration`・`execute_sql` は確認待ちで時間切れになることがある。そのときは依頼者に SQL Editor で実行してもらう（依頼者は SQL Editor の場所を知らなかったため、場所の案内が必要）。
- **一括削除の制限**：マスタ以外を一括で消す処理は、Claude Code の安全確認で止められたことがある。テストデータの入れ替えは、テストデータだけを消す形にしてある。
- **ヘッドレスのブラウザ**：日本語のファイル名のダウンロード・アップロードが試験環境では扱いにくい（アプリの不具合ではない）。
- **プロセスを止めるコマンド**：`pkill -f "http.server ..."` は自分のシェルまで止めることがある。試験用サーバーは別のポートで立ち上げ直すほうが安全。
- **GitHub Pages**：Settings → Pages の Source は「GitHub Actions」に設定済み。

## 9. 新しいアカウントで始める手順

1. **リポジトリ**
   - 公開リポジトリなので読むことはできる。
   - push するには、btshibuya アカウントから新しいアカウントをコラボレーターに招待してもらう（Settings → Collaborators）。
   - Claude Code のセッションでは `btshibuya/ifrs-aje-app` を追加する。
2. **Supabase**
   - 新しいアカウントのセッションから同じプロジェクトを使うには、依頼者が Supabase の組織に新しいアカウントを招待する（Organization → Team）。
   - そのうえで、Claude の Supabase コネクタを新しいアカウントで接続する。
   - アプリそのものは、公開用のキーで動くため設定なしで使える。
   - 別のプロジェクトにする場合は、次の順に進める。
     1. `supabase/migrations` を 0001 から 0013 まで順に実行する。
     2. `src/lib/supabase.ts` の URL・キーを差し替える。
     3. テストデータを入れる。
3. **動作の確認**
   - `npm install` → `npm test` → `npm run dev` を実行する。
   - アプリのURLで、ホーム・連結精算表（当期2Q）・論点の解説が表示されることを確かめる。
4. **最初の報告**：日本語で、URLを付けて報告する。
