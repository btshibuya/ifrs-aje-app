# IFRS 調整仕訳（AJE）起票アプリ　プロトタイプ

日本基準で作成した子会社の財務数値から、IFRSへの調整仕訳（AJE）を起票するWebアプリのプロトタイプです。
プレゼン用のため、ダミーデータ・ログインなしで動きます。

- 画面：React + TypeScript（Vite）
- データ：Supabase（東京リージョン、無料プラン）
- 配色：Word（標準）・Outlook・Excel・PowerPoint・Publisher・OneNote から選べる（ヘッダー右の「配色」）
- DB設計：[docs/db_design.md](docs/db_design.md)、マイグレーション：[supabase/migrations](supabase/migrations)

## できること

| 画面 | 内容 |
|---|---|
| （共通） | 画面右上の「前期／当期 × 1Q・2Q・3Q・期末」で、四半期と本決算を切り替える。四半期は期首からの累計で計算する（累積の論点は前年度末の確定した残高から） |
| ホーム | 作業の流れ（資料を集める → 取り込み・明細チェック → 計算 → 確定）と各段階の件数、対応が必要なこと（差し戻し・確認待ち・期首チェック・貸借不一致・未確定）、資料の提出が遅れている会社 |
| 進捗一覧 | 会社×13論点の状況（未着手／取込済／チェック済／計算済／確定）と、会社ごとの資料の提出数。対象外・重要性なしも表示 |
| 資料一覧 | 論点ごとに子会社の担当者が用意する資料の一覧。全社では会社×論点の提出状況（詳細な進捗一覧）、会社を選ぶと「担当者が用意するもの」と提出ボタン |
| 収集パッケージ | 会計システムから出ない情報を、様式に入力して提出する。入力例・見る場所・用語の説明つき。前期の値（BSは前年度末、PLは前年同期、どちらも直前四半期）を並べて表示し、大きく変わった項目は理由の入力を求める。提出 → 親会社の確認／差し戻し |
| 会社別方針一覧 | グループ共通の方針に会社ごとの上書きを重ねた結果（前提値・理由） |
| 作業画面 | 取込 → 明細チェック → 計算シート → 仕訳・確定（論点1 有給休暇引当金、論点3 減価償却）。上の時点の帯で、四半期・期末を行き来できる（点の色はこの論点の状況） |
| 連結精算表 | 親会社の連結決算担当者向け。全社の IFRS 調整仕訳を、開始仕訳・開始実現仕訳・当期仕訳に分けて集計する（下の「連結精算表」） |
| 論点別影響額 | 会社×論点の当期純利益への影響額 |
| チェック | 期首チェック（前期末にあって当期に出てこない明細）、貸借不一致の仕訳 |
| 変更履歴 | DBが自動で記録した追加・変更・削除（変更前後の値） |
| マスタ | 会社・決算期・論点・仕訳区分・グループ統一科目・経済的耐用年数・列マッピングを、画面から追加・編集・非表示・削除できる（使われているものは削除できず、非表示を案内）。資料・収集様式は参照のみ |

### 検証できるしくみ

- **根拠をたどる**（仕訳タブ）：仕訳の1行 → 計算シートの行 → 明細の内訳（合計の一致を表示）→ 元資料。元資料は、保管している原本のハッシュ値（SHA-256）を計算し直し、取込時の値と一致するか（取り込んだあとに書き換えられていないか）を確かめられる
- **計算の検証**（計算シートタブ）：同じ入力・前提値でもう一度計算し、保存された結果（入力のハッシュ値、集計行、明細ごとの計算過程、科目ごとの仕訳金額、前提値）と一致するかを確かめる
- **検証レポート**（作業画面の右上）：会社×期×論点の証跡を1枚にまとめる（検証の結果、計算の再現、元資料と原本の確認、方針と前提値、集計、科目別の合計（BS→PL）、仕訳、状況の記録）。開いた時点で自動で確認し、印刷・PDFで保存できる
- **記録**（収集パッケージ）：入力開始・下書き保存・提出・確認・差し戻しを、DBの変更履歴からタイムラインで表示する

### 資料と収集パッケージ

- 資料は2種類：**会計システム等から出力**（試算表、固定資産台帳、有給休暇の残日数一覧。ファイルをそのまま提出）と、**収集パッケージに入力**（それ以外）
- 資料・様式の定義（項目、入力例、説明、見る場所、整合チェック）は `src/lib/materials.ts`、入力値は `package_entries`（会社×基準日×様式）
- 基準日は四半期末。比べる値は、残高・率（BS）は前年度末、期間の金額（PL）は前年同期、どちらも直前四半期
- アシスト：入力例の表示（既定でオン）、全角数字・カンマ・△（マイナス）の読み替え、自動計算（消化率など）、整合チェック（退職給付債務の期首→期末など）、期首残高＝前年度末の期末残高の確認と転記、前期から30%以上変わった項目の理由入力、前回の値のコピー、自動保存
- 入力者・状況・下書き保存・提出・次の様式へ・確認済にする・差し戻すは、様式一覧の上のバーにまとめている
- **仕訳のプレビュー**：入力中の値から IFRS 調整仕訳を簡易計算して表示する（`src/lib/preview.ts`）。金額を押すと、参照している入力欄（明細の様式は行・セル）を仕訳の色で強調し、計算式と様式の外の値（方針の率・ほかの様式・取り込んだ明細）を示す
- **Excel**：様式ごとのシートに、今の入力・入力例・前期の値を入れてダウンロードできる（入力欄以外は保護、選択肢は入力規則）。アップロードすると、変わった様式だけを確認してから下書きに取り込む（提出済み・確認済みは変えない）
- 担当者ごとのログインはまだない。入力者名を画面で入れる（ブラウザに覚える）。収集パッケージの画面は会社ごとのURLなので、ログイン導入時は自社だけに絞る

### 明細の入れ方（取込タブ）

- **ファイルを取り込む**（おすすめ）：会計ソフト等の出力（Excel・CSV）を加工せずに取り込む。列名が列マッピングと違うときは、見出しの行と列の候補を自動で選び（社員コード→社員番号、日給→日額給与 など）、例の値を見ながら画面で選び直せる。選んだ対応は、その会社の列マッピングとして保存できる（次回から自動）
- **1件ずつ入力する**：ファイルが出せないときの手入力（資産の種類は経済的耐用年数のマスタから選べる）。Excel の表をコピーして貼り付けるとまとめて入る。全角数字・カンマ・△を読み替え、欄ごとにエラーを出す。入力途中はブラウザに残る
- **合計で入力する**：明細が多い・出せないときに、精度を損なわない単位でまとめて入れる
  - 有給休暇：区分（管理職・一般職など）ごとの残日数の合計と、残日数で加重平均した日額給与（「残日数×日額給与の合計」を入れると自動計算）。加重平均なら1人ずつと同じ金額になる
  - 減価償却：資産の種類×取得年月ごとの合計（定額法・月割りのため、1件ずつと同じ結果）。除却した資産はまとめない
- 手入力の内容は CSV にして元資料として保存し、ファイル取込と同じくハッシュ値で書き換えがないことを確かめられる

### 連結精算表

- **集計の考え方**（`src/lib/consolidation.ts`）
  - 当期仕訳：選んだ時点（四半期末・期末）の各社の計算の仕訳。下書きも含め、「確定した計算だけ」に絞れる
  - 開始仕訳：前年度までの**確定した**計算から作る。累積の論点は前年度までの累計、洗替の論点は前年度末の全額。損益は利益剰余金、OCI はその他の資本の構成要素に置き換える。組換は引き継がない
  - 開始実現仕訳：洗替の論点で、前年度末の全額を期首に戻し入れる（BS は開始仕訳と相殺、損益は当期に入る）
  - 12月決算の会社（S10）は、3か月前までの期（例：親会社の第2四半期 9月末 → S10 の6月末）を使う
- **精算表**：関係する科目だけを、資産・負債・純資産・損益・OCI の順に並べる。列の切り口は「仕訳の種類（開始・開始実現・当期・合計）」「論点別」「会社別」。借方そのまま・貸方△、金額の大きさを色の濃さで表示。貸借の検証（0）と当期利益・包括利益への影響の行つき。セルを押すと、会社×論点×仕訳区分の内訳と元の仕訳・作業画面へのリンクを出す。Excel（区分・小計・検証の行つき）・CSV で出力
- **グラフ**：純資産への影響の橋渡し（開始 → 開始実現 → 当期 → 期末）、論点別（会社別）の当期利益への影響（押すと絞り込み）
- **上書き前後**：「集計する」で、いまの金額を記録する（`consolidation_snapshots`）。そのあとに子会社の仕訳が上書きされたら、「上書き前後を表示」のチェックで、各セルに前の金額と差額を出す（変わった科目だけの表示、内訳での会社別の差も）
- 明細を入れ替えると、確定前の計算は「再計算待ち」として残る（連結精算表では前の仕訳のまま集計し、再計算待ちを表示）。作業画面で「再計算する」を押すと、保存の前に、科目ごとの上書き前・上書き後・差額と当期利益への影響を確認できる
- 開始仕訳・開始実現仕訳・当期仕訳のタブ：論点別／会社別に、合計の仕訳と会社（論点）×仕訳区分ごとの仕訳。CSV 出力

### 計算まで実装している論点

- **論点1 有給休暇引当金（洗替）**：残日数 × 消化見込率 × 日額給与 ×（1＋法定福利費率）。期末の全額と税効果を出力
- **論点3 減価償却（累積）**：経済的耐用年数による定額法（月割り）。当期の変動分（償却額の差・除却時の差）と税効果の変動を出力
  - 前期の確定した計算があれば、その期末残高（IFRS帳簿価額・残存月数）から続けて計算する
  - 前期の計算にない既存資産（アプリ初年度など）は、期首の累積差額を利益剰余金に計上する
  - 期首の繰延税金は前期の税率、期末は当期の税率で計算する

計算ロジックは画面から切り離した関数（`src/calc`）にあり、収集パッケージの入力チェックなど（`src/lib/package.ts`）とあわせて `npm test` で試験できます。

## デモの流れ

0. ホームで、作業の流れ（4段階）と「対応が必要なこと」を見る。ヘッダー右の「配色」で色を変えられる
1. 進捗一覧で「前期」を選び、S01 東都精機の「3. 減価償却」を開く
2. 取込タブのサンプル「S01 2026年3月期」をダウンロードして取り込む
3. 明細チェックで「すべてチェック」→ 計算シートで「計算する」→ 仕訳・確定で「この計算で確定する」
4. 上の時点の帯で「2027年3月期 期末」に移り、「S01 2027年3月期」を取り込んで同じ操作をする
   - 旧型旋盤の除却（除却損の調整）と、台帳から消えた配送トラックの警告（期首チェック）が出る
5. 連結精算表を開く（テストデータで、全13論点の前期・当期1Q・2Qを計算済み。S01 の有給休暇・減価償却は手で試すため空けている）
   - 「当期 2Q」で、精算表の列の切り口（仕訳の種類・論点別・会社別）を切り替え、セルを押して内訳を見る
   - 「上書き前後を表示」をオンにすると、集計のあとに S03 の有給休暇が訂正されて変わった金額（前・差額）が出る
   - 開始仕訳・開始実現仕訳のタブで、前期末からの引継ぎと洗替の戻入れを論点別・会社別に見る
6. 論点別影響額・チェック・変更履歴を見る
   - 仕訳タブの「根拠をたどる」で、仕訳 → 計算シート → 明細 → 元資料（原本のハッシュ値の確認）をたどる
   - 計算シートタブの「この計算を検証する」で、計算を再現して保存結果と一致することを確かめる
7. 資料一覧で S01 を選び、「収集パッケージに入力する」から、2026年3月31日の様式に入力する
   - 前期の値（S01 のデモ用の前期値：2025年3月末・2025年12月末・2026年12月末）が並ぶ
   - 「退職給付の数理計算結果」で「前年度末の期末残高を入れる」→ 入力例の値を入れると、期首→期末のつながりと増減の理由を確認できる
   - 提出すると資料一覧・進捗一覧の提出数に反映され、親会社の「確認済にする」「差し戻す」を試せる

ほかに、S04（弥生会計の列名）の台帳で会社ごとの列マッピング、区分マッピングにない資産種類の警告を試せます。
S03 は2027年3月期から税率が変わり、S10 は在外子会社の税率です（会社別方針一覧）。

## 開発

```bash
npm install
npm run dev        # http://localhost:5173
npm test           # 計算ロジック・収集パッケージの入力チェック・仕訳のプレビュー・連結精算表の集計の試験
npm run build      # dist/ に出力（静的ホスティングで公開できる）
node scripts/make-samples.mjs   # public/samples のサンプルを作り直す
```

main に push すると、GitHub Actions（`.github/workflows/pages.yml`）がビルドして GitHub Pages に公開します（https://btshibuya.github.io/ifrs-aje-app/ ）。
初回だけ、GitHub のリポジトリの Settings → Pages で Source を「GitHub Actions」にしてください。

接続先は `src/lib/supabase.ts` にあります（公開用のキー）。環境変数 `VITE_SUPABASE_URL`・`VITE_SUPABASE_PUBLISHABLE_KEY` で上書きできます。

## テストデータ

「マスタ」画面の「テストデータ」タブで、入れる・消すができます（処理は `src/lib/testData.ts`）。

- **テストデータを入れる**：全13論点について、全社（S01〜S10）の前期（1Q〜期末）と当期（1Q・2Q）のデータを入れます（2〜3分）
  - 収集パッケージ：全様式（当期2Qは提出済・入力中・差し戻しも）と試算表の提出
  - 有給休暇・減価償却：取込 → 明細チェック → 計算 → 確定を、アプリの処理そのもので行う（S01 は手で試すため空けている）
  - そのほかの論点：収集パッケージの入力から仕訳を簡易計算して確定（期間の金額の論点は当期の累計、残高の論点は前年度末からの増減、洗替は期末の全額）。当期2Qの一部は下書き
  - のれん・株式報酬・借入手数料は、一部の会社で「適用」にする方針の上書きを入れる
  - 連結精算表：当期2Qを集計したあと、S03 の有給休暇を訂正（上書き前後を確かめられる）
  - 前に入れたテストデータは入れ替え、画面で入力したものは残す
- **テストデータを全て消す**：テストデータ（`is_demo_seed` の付いたもの）を全て消し、方針の上書きを元に戻す。「画面で入力したものも消す」にチェックを入れると、マスタ以外を全て消す
- コマンドで入れ直すときは `npx vitest run --config scripts/vitest.seed.config.ts`

## 注意（プロトタイプの前提）

- ログインなしで、URLを知っていれば誰でも全データを読み書きできます（`0005_standalone_mode_allow_anon.sql`）。実データは入れないでください
- ログインを導入するときは、0005 の anon ポリシーを削除し、確認者・確定者を必須に戻します
- BTrexの出力レイアウト（区分コード・科目コード）は未対応です。現在の仕訳CSVは汎用の形式です
